# Anime Mysterious — Roblox Tower Defense Prototype

ต้นแบบเกม Anime Tower Defense ที่ใช้ Re:Rangers X เป็นแนวอ้างอิงในการเล่น โดยใช้ชื่อยูนิต ฉาก และรูปทรงที่สร้างขึ้นใหม่ ไม่มีการนำโมเดล โค้ด เพลง หรือภาพตัวละครของเกมเดิมมาใช้

## เปิดเล่นใน Roblox Studio

1. ดาวน์โหลด `AnimeMysterious.rbxlx` แล้วเปิดด้วย **Roblox Studio → File → Open from File**
2. กด **Play / F5** (ต้องใช้ Play เพื่อให้ LocalScript และหน้าจอทำงาน)
3. เลือกการ์ดยูนิตด้านล่าง แล้วคลิก/แตะฐานหมายเลขสีเขียวเพื่อวาง
4. กด **Start Wave** ศัตรูจะเดินจากประตูม่วงไปยังศาลเจ้าสีเขียว
5. คลิกยูนิตที่วางแล้วเพื่ออัปเกรดหรือขาย ป้องกันศาลเจ้าจนครบ 8 เวฟ

แผนที่จะถูกสร้างโดยสคริปต์เมื่อเริ่ม Play ดังนั้นในโหมดแก้ไขอาจเห็นฉากว่าง ซึ่งเป็นพฤติกรรมที่ตั้งใจไว้ ไม่ต้องเปิด HTTP Requests, API Services หรือใช้ปลั๊กอินเพื่อเล่นต้นแบบ

## สิ่งที่เล่นได้

- **Lantern Valley**: แผนที่หมู่บ้านโคมไฟ เส้นทางคดเคี้ยว ฐานวาง 14 จุด
- **Ember Ronin**: 300 เครดิต ยิงเร็ว เน้นเป้าหมายเดี่ยว
- **Frost Oracle**: 400 เครดิต ลดความเร็วศัตรู 50% เป็นเวลา 1.8 วินาที การยิงซ้ำต่ออายุสถานะ
- **Astral Warden**: 550 เครดิต โจมตีเป็นพื้นที่รัศมี 10 studs
- ยูนิต 4 ระดับ ขายคืน 70% ของเงินที่ลงทุนจริง รวมค่าอัปเกรด
- เวฟ 8 รอบ มีศัตรูวิ่งเร็วและ **Rift Sovereign** ในเวฟสุดท้าย
- ยูนิตเลือกยิงศัตรูในระยะที่เดินใกล้ปลายทางที่สุด
- เงินเริ่มต้นคนละ 900 เครดิต วางได้คนละ 12 ยูนิต รางวัลศัตรูและจบเวฟแบ่งให้ผู้เล่นทุกคนเต็มจำนวน
- เลือดศาลเจ้าร่วมกัน 100: ศัตรูทั่วไปหลุดเสีย 8 บอสหลุดเสีย 30
- เวลาเตรียมตัวระหว่างเวฟ 12 วินาที กดเริ่มก่อนเวลาได้
- ความเร็ว x1 / x2 ควบคุมโดยผู้เล่นคนแรกที่ยังอยู่ในเซิร์ฟเวอร์
- เล่นใหม่หลังชนะ/แพ้ด้วยคะแนนโหวตจากผู้เล่นทุกคนที่อยู่ในเซิร์ฟเวอร์
- หน้าจอย่อให้เข้ากับจอเล็ก มีปุ่มสำหรับสัมผัสและคีย์ลัด

### จุดที่ต้นแบบนี้เน้นปรับปรุง

- มองเห็นสนามทั้งด่านด้วยกล้องมุมสูง และเห็นวงระยะก่อนวางด้วยเมาส์/เมื่อเลือกยูนิต
- แสดงราคาอัปเกรด ความเสียหาย ระยะ และเงินขายคืนในจุดเดียว
- เอฟเฟกต์สั้น ไม่สั่นกล้อง และปิดได้ผ่าน **FX OFF**
- เซิร์ฟเวอร์ตรวจเงิน ตำแหน่งฐาน สิทธิ์เจ้าของ จำนวนยูนิต และอัตราคำสั่ง ไม่เชื่อค่าความเสียหาย/เงินที่ส่งจากไคลเอนต์

สิ่งเหล่านี้เป็นเป้าหมายการออกแบบต้นแบบ ยังไม่ใช่ข้อสรุปว่าเกมดีกว่าเกมอ้างอิงจากการทดสอบผู้เล่นจริง

## การควบคุม

กล้องเป็นแบบดูสนามคงที่ ตัวละครผู้เล่นไม่ได้เป็นตัวโจมตีหลัก ปิดการเดิน/กระโดดไว้ในไฟล์ place

## แก้ไขและสร้างไฟล์ใหม่

- `src/Config.lua`: ราคา ดาเมจ ระยะ การอัปเกรด เงินเริ่มต้น และความยากเวฟ
- `src/Server.server.lua`: แผนที่ กติกา ศัตรู การโจมตี และตรวจคำสั่ง
- `src/Client.client.lua`: หน้าจอ กล้อง อินพุต วงระยะ และเอฟเฟกต์
- `default.project.json`: การจัดวาง service สำหรับผู้ที่ใช้ Rojo อยู่แล้ว

สร้างไฟล์ place ใหม่หลังแก้ไฟล์ source:

```sh
cd /workspace/paid/roblox/anime-mysterious
python3 tools/build_place.py
```

ตัวแพ็กใช้ Python standard library เท่านั้น สร้างไฟล์ XML พร้อมบรรจุ source ทั้ง 3 ไฟล์และตรวจว่า source ไม่เปลี่ยนหลังอ่านกลับ ไม่ได้แปลงหรือ compile โค้ดเป็น bytecode

ถ้าแก้สคริปต์ภายใน Roblox Studio โดยตรง ให้บันทึก place แยกไว้ก่อน การรันตัวแพ็กอีกครั้งจะสร้าง `AnimeMysterious.rbxlx` จากไฟล์ใน `src/` ใหม่

## ผลการตรวจสอบและข้อจำกัด

ตรวจผ่านใน cloud:

- ตรวจ syntax Lua-compatible ของสคริปต์ทั้ง 3 ไฟล์ด้วย luaparse
- ทดสอบกติกาโดยรัน source เซิร์ฟเวอร์จริงผ่าน Fengari พร้อม service จำลอง: input ที่ผิด เงินไม่พอ ฐานซ้ำ สิทธิ์ขาย/อัปเกรด เงินคืน การควบคุมความเร็ว การเริ่มเวฟซ้ำ ศัตรูหลุด แพ้ ชนะ โหวตเล่นใหม่ และผู้เล่นออก
- จำลองกลยุทธ์เล่นคนเดียวด้วยค่าดาเมจปกติ ครบ 8 เวฟ โดยไม่ใช้การเพิ่มค่าสเตตัสเพื่อช่วยผ่าน
- การทดสอบ lifecycle แยกต่างหากเพิ่มค่าดาเมจชั่วคราวเฉพาะในหน่วยความจำของการทดสอบ เพื่อครอบคลุมการเปลี่ยนสถานะอย่างรวดเร็ว ไม่แก้ค่าที่ส่งมอบในเกม
- ตรวจ XML ของไฟล์ place และตำแหน่ง Script / LocalScript / ModuleScript

**เครื่อง cloud ไม่มี Roblox Studio จึงยังไม่ได้ตรวจการเปิด place, rendering, อินพุตมือถือ, การ replication หรือ multiplayer ในเอนจินจริง** การจำลองไม่ยืนยันว่า API ทุกตัวทำงานในเอนจิน ต้องตรวจรายการต่อไปนี้ใน Studio ก่อนเผยแพร่:

1. Play หนึ่งผู้เล่น: เห็น UI แผนที่ และยูนิตครบ; Output ไม่มี error
2. วาง Ronin ที่ฐาน 03, 06, 10 แล้วเริ่มเวฟแรก: เงินลด ศัตรูเคลื่อนที่ ยูนิตโจมตี และได้รางวัล
3. เลือกยูนิต: วงระยะ ราคาอัปเกรด และเงินขายคืนตรงข้อมูล
4. Device Emulator: ทดสอบจอแนวตั้ง/แนวนอนและการแตะฐาน/ปุ่มโดยไม่วางยูนิตซ้ำ
5. Start Server สองผู้เล่น: ขายยูนิตคนอื่นไม่ได้ เลือด/เวฟตรงกัน และโหวตเล่นใหม่ต้องครบคน
6. เล่นจนครบเวฟบอส ตรวจชนะ/แพ้ และเล่นใหม่

ต้นแบบใช้โมเดลทรงเรขาคณิต ไม่มีแอนิเมชันตัวละคร ระบบสุ่ม/คลังตัวละคร ล็อบบี้ บันทึก DataStore ร้านค้า หรือ monetization ข้อมูลเงินและยูนิตอยู่เฉพาะรอบปัจจุบัน จำนวนศัตรูและ HP ยังไม่ปรับตามจำนวนผู้เล่น จึงควรปรับสมดุล co-op หลังทดสอบจริง

รันการตรวจจำลองซ้ำ (เครื่องนี้ติดตั้งเครื่องมือไว้นอก checkout แล้ว):

```sh
NODE_PATH=/workspace/setup-validation/roblox-tools/node_modules node tests/validate.cjs
```

เครื่องอื่นให้ติดตั้ง `luaparse@0.3.1` และ `fengari@0.1.5` ในโฟลเดอร์เครื่องมือแยก แล้วตั้ง `NODE_PATH` ไปยัง `node_modules` ของโฟลเดอร์นั้น

## ลำดับพัฒนาต่อที่แนะนำ

เริ่มจากทดสอบความสนุกและความอ่านง่ายกับผู้เล่นจริง ปรับความยาก solo/co-op และต้นทุนอัปเกรด แล้วจึงเพิ่มโมเดล/แอนิเมชันต้นฉบับ ความสามารถกดใช้ ด่านที่สอง ล็อบบี้ และระบบบันทึกข้อมูล ไม่ควรเพิ่มกาชาหรือร้านค้าก่อนวงจรการเล่นหลักลงตัว
